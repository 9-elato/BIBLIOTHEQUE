BIBLIOTHEQUE 두 PC 동기화

PC1: C:\Users\pc1\Documents\GitHub\BIBLIOTHEQUE
PC2: C:\Users\9elat\OneDrive\Documents\GitHub\BIBLIOTHEQUE

이 도구는 GitHub의 main 변경을 받기만 합니다. Codex 원격 제어 연결을 만들거나
미완성 작업을 자동 커밋/Push하지 않습니다. 파일을 복사하는 OneDrive 동기화와 별개입니다.

최초 전달
1. PC1에서 이번 커밋을 Push origin 합니다.
2. PC2 GitHub Desktop에서 Fetch origin -> Pull origin 합니다.
3. PC2 폴더에 START-SYNC.cmd와 scripts/sync-library.mjs이 있는지 확인합니다.

사용
- 수정하지 않고 최신 버전을 받아둘 PC에서 START-SYNC.cmd를 실행합니다.
- 창을 열어둔 동안 60초마다 확인합니다. Ctrl+C 또는 창 닫기로 중지합니다.
- PC2를 주 작업 컴퓨터로 사용할 때는 PC1에서 실행하는 구성을 권장합니다.
- 코드를 수정하기 전에는 해당 PC의 동기화 창을 중지하세요.
- 작업 완료 후 GitHub Desktop에서 Commit -> Push origin 합니다.
- 다른 PC는 변경이 없는 main 브랜치일 때만 fast-forward로 적용합니다.
- 충돌, 수정/추가 파일, 아직 올리지 않은 커밋이 있으면 적용하지 않습니다.
- skip-changes: 로컬 수정/추가 파일이 있습니다.
- skip-unpublished: 로컬 커밋이 원격보다 앞서거나 갈라졌습니다.
- skip-branch: main이 아닌 브랜치 또는 detached HEAD입니다.
- GitHub 로그인 오류는 GitHub Desktop/설치된 Git 자격 증명 설정에서 해결해야 합니다.
  이 도구는 비밀번호를 저장하거나 읽지 않습니다.
- Node.js와 Git이 설치되어 있어야 합니다. PowerShell 실행 정책은 변경하지 않습니다.
- 비정상 종료 후 잠금 파일이 남으면 오류에 표시된 경로를 확인하고, 다른 동기화 창이 없는지 확인한 뒤 해당 잠금 파일만 제거하세요.

설치 범위
로그인 시 자동 시작, 예약 작업, 방화벽 변경, 원격 접속 설정은 하지 않습니다.
로컬 폴더 동기화는 이미 열린 개발 서버의 실행이나 GitHub Pages 배포 성공까지 보장하지 않습니다.
PC2에서 수정하면 PC2 환경에서 테스트하고 Push한 후 배포 결과를 확인하세요.
